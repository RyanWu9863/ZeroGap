# 導讀 10：首頁（第 3 批）

這份是給組員和使用者看的。用白話講第 3 批做了什麼。

## 1. 首頁長什麼樣

最上面是標題「電影、晚餐、回家的車，每一段都接得上。」，標題下面是三個大數字，數字下面是一面會動的點陣。
中間是四格快速條件：商圈、出發、日期、預算。填完按「排行程」就直接排，不用走四步精靈。
就像點餐櫃台：四個問題答完，菜就開始做。
想細調的人，按「更多條件」進入完整的四步精靈。
四格下面有「常見情境」小按鈕。它只會幫你填好條件，不會自己送出。

為什麼是四格不是三格？車站資料沒有座標，前端算不出離哪個商圈最近，所以商圈要讓使用者自己選（規格 D13）。

首頁下半部還是原本的時間軸預覽、痛點對照、三步驟。舊的 `Hero.tsx` 已刪除。
三步驟最下面的「開始規劃」會捲回上面的四格、焦點放在第一格（同一頁只有一個「開始」的地方）；旁邊另有「或用四步精靈規劃」。

## 2. 點陣剪枝在說什麼

比喻：一面燈牆，每盞燈是一種「電影＋餐廳＋回家班次」的組合。
動畫開始時全部亮著。接著照真實比例把不合格的燈熄掉，最後只剩 3 盞亮得特別大的，就是推薦的三個方案。

為什麼只有三層？因為後端只告訴我們「全部組合數 → 可行組合數 → 方案數」，沒有每一道關卡各剩幾個。
沒有的數字我們不編，所以動畫只畫這三層：全部 → 可行 → 方案。

最後一幕長這樣：被剪掉的點是灰色（透明度 0.15）；可行的點是淡青色小點（3px、透明度 0.4）；3 個方案點是亮的大點（6px，有光暈）。動畫約 3.3 秒。
每個點不一定代表一種組合。組合太多時會抽樣，畫面上有一行小字「每點約代表 N 種組合」。

## 3. 數字從哪來

大數字優先用「上次真實規劃的結果」，存在瀏覽器的 `zg-plan-runs`。
還沒排過的人，看到的是示範數字：73,038 → 1,201 → 3，旁邊標「示範」。這組數字來自後端真實的測試資料，但程式執行時不會去讀那份檔案，而是直接寫在 `heroStats.ts`。
用假後端（開發、展示站）排過的話，數字是假資料編的，所以小字寫「你上次排的（假資料，時間）」，不會被當成真數字。

## 4. 手機和效能

- 點的數量有上限：手機（寬度小於 640px）最多 4000 點，桌機最多 12000 點。
- 手機上點陣比較矮（高 160px，電腦 288px），四格表單才不會被擠到第一個畫面外面；載入前佔位的高度跟著一樣，版面不跳。
- 點陣用 Canvas 畫，而且延遲載入，不擋首頁文字出現。
- 車站和日期的彈出選單也延遲載入，保護最大內容繪製時間（LCP）。如果使用者在載入完成前就按了，系統會記著，載入好立刻打開。
- 實測：慢速 4G 下首頁 LCP 是 1.83 秒（目標小於 2.0 秒；最終審查修正後重量）。
- `npm run predemo`（最終審查修正後，19:34 跑完）：vitest 183 個全過；Playwright 277 通過、75 略過、0 失敗。

## 5. 減少動態和無障礙

- 系統設定「減少動態」時，點陣不播動畫，直接顯示最後一幕。
- Canvas 本身對讀屏軟體隱藏（`aria-hidden`）。同樣的資訊用看得見的數字行和「每點約代表 N 種組合」說明文字提供。
- 有格子沒填就按「排行程」：不送出，焦點跳到第一個沒填的控制項，錯誤文字用 `aria-describedby` 連到它（只掛在選項上，不掛在整組上）。
  表單上方只有一個 `role="alert"`，念第一個沒填的格子和「還有 N 格沒填」，不會每格各念一次。
- 「哪天」查不到場次日期（連線失敗）時，只在那一格說明＋重試，其他格照樣能改。

## 6. 晚上的日期自動修正

比喻：過了打烊時間，店會自動幫你改約明天。
如果今天的出發時間已經過了，日期會自動換成最近還排得到的日子，並提示「今天 HH:MM 已經過了，換成最近可以排的 M/D」。
日期本身不能用也會換，提示照實講原因：日期已經過了是「原本的日期已經過了，換成…」，那天沒有場次是「那天沒有場次，換成…」。
這個規則首頁和精靈共用（`frontend/src/features/wizard/useDateAutoFix.ts`，規格 D15）。使用者在**同一個畫面**裡自己選的日期、自己改過的出發時間，不會被蓋掉；
但這個「自己選過」只記在那個畫面裡：在首頁選了今天，再進精靈第 2 步，如果今天的出發時間已過，還是會被換掉並說明。
順手修了一個舊測試：它每天 17:00 之後都會失敗，現在固定用未來的日期。

## 7. 改了哪些檔案

都在 `frontend/src/features/home/` 底下：

- `HomeHero.tsx`：標題、大數字、延遲載入的點陣畫布
- `QuickPlanForm.tsx`：四格表單，匯出名稱是 `QuickPlan`。檔名不叫 `QuickPlan.tsx`，因為會和 `quickPlan.ts` 在 macOS／Windows（不分大小寫）撞名
- `dotModel.ts`：點的排列和數量（`layoutDots`、`dotCount`、`MAX_DOTS`、`PHONE_BREAKPOINT`）
- `heroStats.ts`：大數字的來源
- `quickPlan.ts`：`quickDate`、`quickMissing`、`dateIssue`
- 共用的 `frontend/src/features/wizard/useDateAutoFix.ts`（首頁和精靈都用）

另外：舊的 `Hero.tsx` 刪除；規格加了 D13（四格）、D14（三層點陣，不編造每關數字）、D15（晚上規則）；README 更新首頁一節。
