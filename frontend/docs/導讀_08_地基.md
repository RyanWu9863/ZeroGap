# 導讀 08：地基（第 2 批）

這份是給組員和之後接手的人看的。用白話講第 2 批做了什麼。

## 1. 這一批做了什麼

把「優化版」前端整條搬進團隊的 `frontend/`。三版試做稿只留一個版本。
加了夜／日兩套外觀、換了新字體、做了新外框（導覽列和頁尾）。
最後補上團隊 repo 根目錄的前端 CI。
就像新家先把水電、牆面、地板弄好，家具（新頁面）留到後面幾批再搬。

## 2. 為什麼整條合併，不一個一個搬

比喻：搬家時，把整個房間連櫃子一起打包，比一件一件拆開再重組快，也不會少東西。
11/07 試過：逐檔搬 11 個檔案，就出現 5 個型別錯誤。
整條合併（來源是私人 repo `Samuelsunshine/zerogap-frontend` 的 `integrate/backend-v0.9-main`，共同祖先 `ec906eb`）則是零衝突、`tsc` 零錯誤、當時 146 個單元測試全過。
來源先追上該 repo main 的 PR #5～#9（到 `5a355fe`）才合併。

## 3. 夜和日怎麼運作

- `src/shared/theme/theme.ts` 有三個主要東西：`resolveTheme`（算出現在是夜還是日）、`nextPref`（按鈕下一個狀態）、`useApplyTheme`（把結果套到網頁上）。
- `index.html` 裡有一小段腳本，在頁面畫出來之前就先決定夜或日，所以不會先閃一下白畫面。
- 你選的結果存在瀏覽器的 `zg-theme`。
- CSS 只改「顏色變數」不改元件：`src/index.css` 裡 `:root` 是日，`[data-theme="night"]` 是夜。
- 無障礙掃描（axe）在 8 個頁面 × 2 種外觀都通過。

## 4. 字體

- Noto Sans TC（思源黑體）：中文內文。
- Archivo：英文和數字的標題。
- IBM Plex Mono（5.3.0）：時間、代號這類等寬字。
- 用 `src/fonts.css` 非同步載入：字還沒到就先用系統字，不擋住畫面出現。
- `npm run perf` 在手機慢速 4G 下量到的 LCP：首頁 1.71 秒、精靈第 1 步 1.68 秒（目標小於 2.0 秒）。

## 5. 外框

- 頂部導覽（電腦）和底部導覽（手機）共用同一份 `NAV_ITEMS`（在 `src/app/BottomNav.tsx`）。
- 連結用一般的 `<Link>`，目前頁面由 `match()` 決定並標上 `aria-current`。
- 第 5 批要加頁面：在 `NAV_ITEMS` 加一筆，兩種導覽就同時有了。
- 頁尾 `SiteFooter.tsx` 寫資料更新時間（`latestUpdate()`，會略過讀不懂的時間）和資料來源：TDX、開眼電影網、OpenStreetMap、Google 地圖。

## 6. 測試和 CI

- `npm run predemo` 是 Demo 前一鍵檢查。這批最後一次結果：Vitest 154 個通過；Playwright 221 通過、75 略過、0 失敗。
- 新的 `.github/workflows/frontend-ci.yml` 在 Ubuntu 和 Windows 各跑：tsc、lint、單元測試、build、Playwright（chromium）。
- 有一個定位測試偶爾失敗：原因是測試沒等到 `zg-plan` 裡出現 `origin_lat` 就去檢查。
- 修法是等到有了再檢查。修好後重複跑 10 遍（共 40 次）全過。
