# 導讀 11：結果頁（第 4 批）

這份是給組員看的。用白話講第 4 批做了什麼：排程中的漏斗、結果頁的錶盤、分享頁、真實路線地圖。

## 1. 新流程

```
首頁四格（或精靈「更多條件」）
   ↓ 按「排行程」
/result?...   排程中：漏斗（7 個階段，看真實進度）
   ↓ 排好了，換到
/p/編號       結果頁（網址是分享連結，重新整理不會重排）
```

分享給朋友的連結、MCP 回傳的 `share_url`，開的都是同一頁 `/p/編號`。
第 2、3 個方案的網址多一個 `?plan=2`、`?plan=3`；開發用的 `?mock=…` 會跟著帶，其他參數不帶。
編號是 32 碼小寫英數字（`job_id`）；格式不對的網址直接顯示「找不到」，不會去問後端。
排好時，同一台瀏覽器排過的行程先拿來用，不用再問後端。

漏斗畫面：七個階段照 `features/result/stages.ts`。排隊時寫「前面還有 N 個人」（0 個人時寫「下一個就輪到你」）；
等交通資料時寫「交通資料查詢中，約 N 秒」（沒給秒數就不寫秒數）。
螢幕閱讀器只會念目前的階段。排完後三個亮點會飛成三張方案卡。

## 2. 錶盤怎麼看

像一個沒有指針的鬧鐘：

- 一圈是「出門」到「到家」，畫成一段 300 度的弧，底下留一個缺口；從 12 點鐘方向往左 150 度開始，順時針畫。中間寫出門和到家的時間。
- 每一段行程一種顏色：搭車是青色實線、走路是青色虛線、電影是前景色（黑／白）、用餐是灰色、候位是淺灰框線色。圖下面有圖例，只列出這個方案真的有的種類。
- 聚光燈：整個行程裡「緩衝最小」的那一段（一樣小就取最前面那段）會亮一個小圓點，顏色是緩衝三色：寬鬆綠、剛好黃、偏緊紅。
- 點圓點（鍵盤也能按），會展開一句話說明如果出狀況會怎樣：趕不上開演、趕不上最後點餐、趕不上預定那班車、可能趕不上末班車（依那一步是哪種緩衝而定）。
- 三個方案可以用 ← ／ → 鍵、或手機左右滑切換（滑動只認觸控，兩指縮放照常能用）。減少動態時，弧線直接畫好、圓點不跳動。

## 3. 分享頁

三種狀態：

| 狀態 | 條件 | 畫面 |
|---|---|---|
| 正常 | 分享連結還沒過 7 天，而且至少一個方案還沒出發 | 結果頁照常 |
| 過期 | 超過 7 天，或每個方案的出發時間都過了 | 上方橫幅「這份行程已經過期」，行程內容還看得到；分享、加到行事曆不能按；可以用同樣條件重排 |
| 找不到 | 編號亂打、沒排過、或後端已經刪掉 | 「找不到這份行程，可能已經超過 7 天」，可以自己重新排 |

- 結果頁有三個動作：分享連結、加到行事曆（下載 .ics）、改條件重排。手機上「分享連結」在底部固定列，提醒文字就在它上面；電腦版在右欄。
- 從「目前位置」出發的行程，連結裡含出發的大概位置（約 100 公尺內）。分享按鈕旁會提醒「只傳給信任的人」。座標照原樣存在後端（2026-11-07 使用者決定）。
- 展示版（假資料模式或展示模式）的分享連結只在同一台瀏覽器打得開，按鈕旁照實說。
- 每個方案底下有「這個方案怎麼來的」：這次算了幾種組合、幾種每段都接得上、挑出幾個。

## 4. 地圖

地圖在結果頁的右側（中等寬的螢幕在時間軸下面，寬螢幕移到時間軸旁邊）。有兩種看法：Google 地圖、簡潔示意圖。

- 走路：用 Google 的步行路線。
- 搭車：畫起訖站之間的線並標車種，班次照我們排的，不用 Google 建議的班次。
- 餐廳如果只有 Google 的 `place_id`，用 Places 查位置。
- 地圖下面有一行說明：路線還在查時寫「正在查走路路線…」；有幾段走路查不到路線時寫「有 N 段走路查不到路線，先用直線虛線示意」；都查到了才寫「走路是實際步行路線」。
- 沒金鑰（`VITE_GOOGLE_MAPS_KEY` 空白）時只有示意圖，畫面用白話說明目前沒有開啟 Google 地圖。

**要開哪些 API**：Google Cloud 專案要在這把金鑰上啟用 **Maps JavaScript API、Routes API、Places API (New)**，並綁帳單。
少開 Places，餐廳只有 `place_id` 時查不到位置，整張地圖就退回路線示意圖（畫面會說原因）；少開 Routes，走路段就一直是直線虛線（畫面會說查不到）。

**還沒驗證**：真實金鑰的那條路（Routes、Places 真的回資料）還沒跑過，因為目前沒有金鑰。測試用假的 Google 物件驗過邏輯；有金鑰後要實際打開結果頁看一次。

**價目**（2026-11-07 查的官方價目；每月免費量／超過後每千次）：

| 項目 | 每月免費 | 超過後每千次 |
|---|---|---|
| Dynamic Maps | 10,000 | US$7 |
| Routes：Compute Routes Essentials | 10,000 | US$5 |
| Places：Place Details Essentials | 10,000 | US$5 |

怎麼省：
- 查到的路線和位置用分享編號存在瀏覽器（localStorage），7 天後丟掉；同一個查詢同時只送一次。
- 地圖捲到離畫面 300px 以內才載入；沒捲到就不算一次地圖載入。

## 5. `?exp=1` 拿掉了

舊的沉浸式新版（`?exp=1`）零件都刪了，改成正式的新流程。舊網址 `?exp=1` 或 `?exp=0` 不會壞：參數被忽略，看到的就是新畫面。

## 6. 無障礙和效能

- axe 掃描（WCAG 2.1 A／AA，日、夜兩個主題）新增排程中的漏斗和 `/p/編號`，零個嚴重或重大問題。
- 掃的時候發現漏斗還沒輪到的階段，文字被整列的透明度壓淡，對比不夠。已拿掉那層透明度（還沒輪到的階段仍用灰色字，現在對比夠了）。
- 慢速 4G 的首頁 LCP：1.86 秒（目標小於 2.0 秒）；一般 4G 0.56 秒。`/p/:id` 是延遲載入，沒有動到首頁的包。
- 手機底部固定列最多可能有三行提醒，窄螢幕下要自己看一眼。
