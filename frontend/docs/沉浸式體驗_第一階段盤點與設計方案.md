## 1. 現況盤點【事實】

### 1.1 技術架構

| 層 | 用什麼 | 跟這次有關的地方 |
|---|---|---|
| 框架 | React 19、Vite 8、TypeScript 7、React Router 8 | — |
| 樣式 | Tailwind v4＋shadcn（@base-ui/react）；三個試做版用 `cine:`／`lin:` 變體 | 改任何畫面都要三版一起看 |
| 動畫 | **Motion 14**（已安裝） | `layoutId` 共享元素轉場、`AnimatePresence` 都能直接用，不用加套件 |
| 圖表 | Recharts 3（只在系統幕後，延遲載入） | 漏斗的長條圖和桑基圖 |
| 地圖 | **沒有地圖套件** | 目前是手畫的 SVG 示意圖＋Google 地圖連結 |
| 狀態 | Zustand（條件、方案）＋TanStack Query（API） | — |
| 測試 | Vitest 75 個、Playwright 4 種瀏覽器＋axe | 改畫面要跟著改測試 |

### 1.2 「JEV／LLM 分析」實際上的資料流

```
精靈 ④ 送出 → POST /api/itineraries（一次請求、一次回應，沒有串流）
          → 回應裡一次拿到：funnel_stats（總數＋每關剔除數）、top_3_proposals、confidence_gate
          → 前端 FilterRun 動畫 → 結果頁
```

| 問題 | 答案 |
|---|---|
| 後端有沒有逐步回傳進度？ | **沒有**。只有一個 POST，回應一次到齊（`src/api/client.ts`） |
| 有沒有每一關淘汰幾組？ | **有**，`funnel_stats.by_filter`（API 提案 #7，目前假資料有、真後端還不一定有） |
| 有沒有被淘汰的個別候選和原因？ | **沒有**。這是 API 提案 #10，排在 v2 |
| 有沒有每一步的時間戳記？ | **沒有**。前端只能量「送出到收到」的總時間 |
| LLM 有沒有參與？ | `llm_status: '未啟用'`；排序是 Jev 模擬模式。**目前沒有任何 LLM 推理可以呈現** |
| 排序依據 | `confidence_breakdown`（選片機率 × 選餐廳機率）＋`confidence_gate` 閥門 |
| 現在用的資料 | **全部是假資料**（`VITE_USE_MOCK` 預設開），後端還沒串 |

### 1.3 現有的篩選動畫（`result/FilterRun.tsx`）

- 等回應時：五道關卡都顯示「檢查中」轉圈。
- 回應到了：依序打勾，數字從總數往下跳（數字是真的，來自 `by_filter`）。
- **誠實度問題**：等待時的「檢查中」看起來像前端正在即時看到每一關的進度，但其實後端還沒回任何東西。依你的原則，這一段要改。

### 1.4 三方案（`result/PlanSwitcher.tsx`）

- 3 張摘要卡橫排，第一名置中、稍大（決策 Q20）；手機左右滑（Q64）。
- 點卡片 → 下方時間軸換成那個方案；方案寫進網址 `plan=`。
- 沒有「展開詳情」，因為時間軸本來就直接在頁面上（Q36：主角是時間軸）。
- **沒有任何圖片素材**：資料裡沒有影城、餐廳的照片，`public/` 只有 logo 和預覽圖。

### 1.5 地圖（`result/RouteSketch.tsx`）

- 手畫 SVG：依時間軸順序把地點連起來（**已經有順序和連線**），交通用實線、步行用虛線，**標明「非實際比例」**。
- 點地點、按「在 Google 地圖查看完整路線」→ 開 Google 地圖網頁（不需要金鑰）。
- **資料裡沒有座標**：`place.lat／lng` 是選填，假資料全部沒填；API 提案 #2 只寫「最好再加座標」。
- 沒有路線幾何、距離資料；只有每段的分鐘數（寫在文字描述裡）。

### 1.6 系統幕後（`behind/`）

- 方法說明、五道關卡漏斗（**長條圖和桑基圖兩版可切換**，Q67）、機率表＋閥門、資料來源、展示模式、Agent 接口、原始 JSON。

## 4. 時程建議【建議】

今天 10/23，試用約 10/31，投票後到 11/2 Demo。這個需求至少是 **4～6 個工作天**的量。

**建議：做在開關後面，`?exp=1` 才看得到新版**
- 試用和三版比較完全不受影響（預設畫面不變）。
- 團隊可以拿現有版和新版並排比較（符合你說的「先做可比較的版本」）。
- 投票後再決定新版要不要變成預設。

分 5 個 PR，每個 PR 都跑完整檢查才合併：

| PR | 內容 | 依賴 |
|---|---|---|
| 1 | 視覺規則（色彩、層級、動畫節奏、狀態元件）＋ `?exp=1` 開關 | 無 |
| 2 | 篩選漏斗動畫（狀態式等待＋真實數字重播＋可展開關卡） | 1 |
| 3 | 電影式三方案＋共享元素展開詳情 | 1 |
| 4 | 地圖：簡潔模式升級＋實際地圖模式（看第 5 節的決定） | 3（詳情裡要放地圖） |
| 5 | 幕後三版切換（漏斗／時間軸／決策比較） | 2（共用漏斗元件） |

順序跟你給的一樣，只是把「統一視覺規則」放最前面，避免後面每個元件各做一套。

## 5. 地圖要你選【待決定】

| 方案 | 要什麼 | 好處 | 壞處 |
|---|---|---|---|
| (a) 只升級 SVG 示意圖 | 不加套件、不用金鑰 | 零風險、跟三版風格一致 | 不是真的地圖 |
