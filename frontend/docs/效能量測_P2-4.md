# 效能量測：手機 4G 首頁載入（計畫 P2-4）

> 2026-10-22｜目標：首頁 LCP（最大的內容出現在畫面上的時間）在 2.5 秒內（Google 的「良好」標準）
> 量測工具：`npm run perf`（`scripts/measure-perf.mjs`，Mac、Windows 都能跑）

## 1. 結論

**優化前，慢速 4G 的首頁 LCP 約 3.0 秒，超過標準；優化後是 1.64 秒，快了 45%。** 一般 4G 從 0.90 秒變成 0.50 秒。

| 網路 | 頁面 | LCP 優化前 | LCP 優化後 |
|---|---|---|---|
| Slow 4G（Lighthouse 手機標準） | 首頁 A 時刻表 | 2.98 秒 | **1.64 秒** |
| Slow 4G | 首頁 B 電影感 | 3.03 秒 | **1.65 秒** |
| Slow 4G | 首頁 C Linear 風 | 2.97 秒 | **1.64 秒** |
| Slow 4G | 精靈第 1 步（直接開網址） | 2.41 秒 | **1.60 秒** |
| 一般 4G | 首頁 A 時刻表 | 0.90 秒 | **0.50 秒** |
| 一般 4G | 精靈第 1 步 | 0.60 秒 | **0.44 秒** |

## 2. 怎麼量的

- 用 Playwright 的 Chromium 模擬中階 Android 手機（Pixel 7 的畫面尺寸），**CPU 慢 4 倍**。
- 網路分兩種：
  - **Slow 4G**：延遲 150ms、下載 1.6 Mbps，和 Lighthouse 手機版的標準一樣，是比較嚴格的情況。
  - **一般 4G**：延遲 60ms、下載 9 Mbps，比較接近台灣平常的 4G。
- 每次都開全新的瀏覽器環境（沒有快取，等於第一次造訪），每種情況量 3 次取中位數。
- 量的是打包後的正式版（`vite build` 加 `vite preview`），不是開發模式。
- 【限制】這是電腦模擬，不是真的手機。真機的數字會因為手機和訊號不同而有差異，但前後比較的趨勢可信。

## 3. 原本慢在哪裡（追蹤每個檔案的下載時間）

| 時間點 | 發生什麼 |
|---|---|
| 0～1.42 秒 | 下載 CSS（101 KB），**這段期間畫面不能畫**。其中 9 成是四套字型的 `@font-face` 宣告 |
| 0～2.27 秒 | 下載主程式 JS（257 KB）。單頁應用程式要等 JS 跑起來才有畫面 |
| 2.46 秒 | 第一個畫面出現（FCP） |
| 2.98 秒 | 首頁的大字說明**從透明淡入**完成，才被算成 LCP，比 FCP 多等了 0.5 秒 |

主程式裡最大的幾塊：動畫（motion）、React、路由，以及 **@base-ui＋floating-ui**。最後這組只有結果頁的「改條件小視窗」會用到，首頁卻也一起下載。

## 4. 做了什麼

| 改動 | 效果 | 檔案 |
|---|---|---|
| 精靈、結果頁改成用到才下載（原本只有系統幕後這樣做） | 首頁的 JS 從 257 KB 降到約 207 KB；@base-ui 不再出現在首頁 | `src/app/router.tsx` |
| 首頁畫好後，趁瀏覽器有空先下載精靈的程式 | 按「開始規劃」照樣馬上出現 | `src/features/intro/IntroPage.tsx` |
| 字型宣告拆到 `src/fonts.css`，改成不擋畫面的方式載入 | 會擋住畫面的 CSS 從 105 KB 降到 **10.5 KB** | `src/fonts.css`、`src/main.tsx`、`src/index.css` |
| 明體（只有 B 電影感用）拆到 `src/fonts-serif.css`，切到 B 才載入 | A、C 版少下載 44 KB 的字型宣告 | `src/fonts-serif.css`、`src/shared/theme/proto.ts` |
| 首頁的標題、說明、按鈕不再從透明淡入，只保留輕微往上滑 | LCP 不用多等動畫的 0.5 秒 | `src/features/intro/Hero.tsx` |

字型本來就是「先用系統字型顯示，下載好再換」，所以字型宣告晚一點載入，不會讓版面跳動。已經用截圖確認：A 版標題用黑體，B 版切換後用明體。

## 5. 還可以再做、但目前不必要的

- **字型檔還是很大**：首頁會下載 13～23 個字型分段，共 0.8～1.6 MB。它們在畫面出現**之後**才下載，不影響 LCP，但會用掉使用者的流量。之後如果要省流量，可以只保留介紹頁真正用到的字，或標題改用系統字型。（【建議】列為 P3）
- **動畫套件（motion）**：首頁就要用，拆不掉；改用 LazyMotion 大約可以再省 20～30 KB，但要動到很多檔案，效益不大。

## 6. 之後怎麼重新量

```bash
npm run perf
```

最後一行會告訴你「全部 LCP 都在 2.5 秒內」，或是哪一頁超過。改了大功能（例如新增套件、首頁加圖片）之後，建議再跑一次。
