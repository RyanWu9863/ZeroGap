# 導讀 09：結果頁的真實地圖

> 2026-11-07｜對應規格 D10「Google 互動地圖」｜分支 `feat/map-default`

## 1. 這次改了什麼

以前，可以縮放、拖曳的 Google 地圖只有在網址加 `?exp=1` 才看得到。現在**結果頁預設就有**。

- 有設定 Google 地圖金鑰：一打開就是真實地圖。電腦上用滑鼠拖曳移動、按 ＋／－ 或 Ctrl＋滾輪縮放；手機上用兩根手指拖曳、縮放（一根手指是捲動網頁，才不會卡在地圖裡）；點編號標記會看到那一站的時間和要做的事。
- 沒有金鑰：自動改用「路線示意圖」，並用白話說明「這個網站目前沒有開啟 Google 地圖」。一般人看不到「金鑰」這種開發用語；開發模式（`npm run dev`）才多一句設定提示。
- 不管哪一種，都有「在 Google 地圖查看完整路線」和「在 Google 地圖開啟這一站」兩種連結。這兩種是一般網址，不用金鑰、不收費。

比喻：地圖像店裡的電視。插上電（金鑰）就播真實畫面；沒插電就貼一張手繪路線海報，旁邊的「去 Google 看」連結一直都在。

## 2. 為什麼不用免費的開源地圖

Google 來源的餐廳只有 `place_id`，沒有座標（Google 規定不能存座標），開源地圖放不上去。所以真實地圖只能用 Google 的（規格第 5 節）。

## 3. 目前還沒做的（第 4 批）

- 站和站之間現在畫的是**直線**，畫面上有寫「不是導航路線」。第 4 批會把走路段換成真的步行路徑，搭車段照我們排的班次畫。
- 夜／日兩套外觀的地圖配色（要在 Google Cloud 建「地圖 ID」並設定樣式）。

## 4. 怎麼申請金鑰（使用者要做）

> 費用（2026-11-07 查 Google 官方價目）：Maps JavaScript API 的「Dynamic Maps」**每月前 10,000 次載入免費**；超過後每 1,000 次 7 美元（1 萬～10 萬次這一級）。Google Cloud 要先建立帳單帳戶才能用。專題 Demo 的用量遠低於免費額度，但建議設預算提醒。

1. 到 Google Cloud Console（console.cloud.google.com）建立或選一個專案，連結帳單帳戶。
2. 「API 和服務」→「程式庫」→ 啟用 **Maps JavaScript API**。
3. 「API 和服務」→「憑證」→「建立憑證」→「API 金鑰」。
4. 點開這把金鑰設定限制：
   - **應用程式限制**選「網站」，加入：`http://localhost:5173/*`、`http://localhost:5175/*`、`https://ryanwu9863.github.io/*`。
   - **API 限制**只勾 Maps JavaScript API。
5. 「帳單」→「預算與快訊」設一個小預算（例如 5 美元）的 email 提醒。
6. 在 `frontend/.env` 加一行 `VITE_GOOGLE_MAPS_KEY=你的金鑰`（`.env` 不會進 git）。重開 `npm run dev` 就會看到真實地圖。
7. 想放上 GitHub Pages 展示站：請 repo 擁有者（RyanWu9863）在 GitHub 的 Settings → Secrets and variables → Actions 新增 `VITE_GOOGLE_MAPS_KEY`，並在 `.github/workflows/pages.yml` 的打包步驟帶進去。這一步會讓公開網站開始使用金鑰，**做之前要先問過使用者**。

瀏覽器金鑰一定會被別人看到（它就寫在網頁裡），所以靠第 4 步的「只限這些網域」來保護。
