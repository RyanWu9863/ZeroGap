# 導讀 01：骨架與兩版試做稿

> 給自己看的白話說明（決策 Q76）。發表時被問「這段怎麼做的」，看這份就答得出來。
> 對應時程：第 1–2 天（決策 Q90）。

---

## 1. 一句話

這一版做了**房子的骨架**（資料夾、路由、跟後端溝通的管道），以及**兩個樣品屋**（介紹頁、結果頁），分別用「A 時刻表」和「B 電影感」兩種裝潢，讓組員投票。

## 2. 整個程式像一間餐廳

| 程式的部分 | 檔案 | 比喻 |
|---|---|---|
| 驗貨單 | `src/api/schemas.ts` | 後端送來的資料先照這張單檢查（zod），少欄位就退貨，不讓錯的東西上桌 |
| 出餐口 | `src/api/client.ts`、`queries.ts` | 跟後端拿資料的唯一窗口；「假資料開關」也在這裡 |
| 點餐單 | `src/store/planStore.ts` | 記使用者填的條件和目前選哪個方案，重新整理不會不見 |
| 假菜 | `src/mocks/` | 後端還沒好之前先用的假資料，照 API.md 的範例做 |
| 調味規則 | `src/shared/lib/` | 緩衝分級、日期金額格式、Google 地圖連結、複製文字，全部有測試 |
| 共用餐具 | `src/shared/ui/` | 緩衝標籤、金額（含黃底）、步驟圖示，兩頁都用 |
| 各個包廂 | `src/features/intro`、`result` | 每一頁一個資料夾，要改結果頁就只看 `result/` |

## 3. 兩版試做稿是怎麼做到的

兩版**共用同一份畫面程式**，只換「設計代號」（顏色、字體、圓角）。

- 代號寫在 `src/index.css`：`:root` 是 A 時刻表，`[data-proto="cinematic"]` 是 B 電影感。
- 左下角的切換鈕會把 `<html data-proto="...">` 換掉，整頁就換裝潢。
- B 版多了一個背景：`src/shared/theme/LightTrails.tsx`，用程式畫的光軌（決策 Q43）。

**比喻**：同一間房子，換一套壁紙和燈光。投票後把沒選上的那組代號刪掉就好，不用重寫畫面。

## 4. 結果頁的重點：「保證接得上」怎麼被看見

1. **時間軸每兩步之間有緩衝標籤**，例如「✓ 開演前還有 10 分・剛好」。三種顏色：綠色寬鬆（≥30 分）、藍色剛好（10–29 分）、橘色偏緊（<10 分）。門檻在 `src/shared/lib/config.ts`。
2. **緩衝分鐘數由後端算**，前端只負責顯示（決策 Q41，符合「時間只由 Python 計算」的鐵律）。這就是 API 變更提案 #1。
3. **估計值黃底**：`Money` 元件，黃底加「約」，還有 ⓘ 說明（驗收 A8）。
4. **預算在花費區打勾**：「✓ 未超過預算 $1,000，還剩 $450」。

## 5. 這一版發現並修掉的 bug

**複製按鈕在某些瀏覽器沒反應**：有些瀏覽器（例如 LINE 內建瀏覽器）不允許網頁寫入剪貼簿。現在的處理順序是：

1. 先試新方法；
2. 被擋下就改用舊方法；
3. 兩種都失敗，直接把行程文字秀出來讓使用者手動複製。

## 6. 誠實標示

- 頂部的「假資料（開發用）」標籤：只要還在用 `src/mocks`，就會一直顯示。
- 介紹頁的範例時間軸標了「範例」；痛點對比的左欄標了「示意」。
- 假資料的日期改成 10/30，因為基準案例 10/15 已經過了（見 API 變更提案 #5）。
