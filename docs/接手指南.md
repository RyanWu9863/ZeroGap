# 接手指南：ZeroGap 前端

> 寫給接手開發的組員。2026-10-22 由陳宣宏（Samuelsunshine）交接。
> 看完這份大約 10 分鐘，就能把專案跑起來，並知道下一步要做什麼。

## 1. 先把專案跑起來（Mac、Windows 都一樣）

1. 安裝 **Node.js 24**（nodejs.org 下載 LTS；最低 22.12）和 Git。
2. 接受 GitHub 的協作邀請後，下載專案：

   ```bash
   git clone https://github.com/Samuelsunshine/zerogap-frontend.git
   cd zerogap-frontend
   npm ci
   npx playwright install chromium webkit
   ```

3. 開發：

   ```bash
   npm run dev
   ```

   瀏覽器打開 http://localhost:5173 。預設用**假資料**，不需要後端。

4. 推程式之前跑一次完整檢查，最後一行出現「✅ Demo 前檢查全部通過」才推：

   ```bash
   npm run predemo
   ```

   這行指令會跑型別檢查、95 個單元測試、流程、元件與無障礙測試（桌機 Chromium、桌機 WebKit、iPhone、iPad；用打包後的正式版跑，和 CI 一樣），最後打包。

## 3. 專案的幾條規矩

- **核心價值是「零空檔：保證接得上」**：畫面主角是時間軸和每一段的緩衝。
- **不是約會 App**：是娛樂、餐廳、交通的行程規劃。畫面上不要出現「約會」。
- **使用者畫面不出現 AI、Jev、機率**：這些只放在「系統幕後」頁。
- **時間和金額只能由後端（Python）算**：前端只負責顯示，不自己算緩衝。
- **三個試做版**（A 時刻表、B 電影感、C Linear 風）共用同一套元件，只換設計代號。改樣式時三版都要看：網址加 `?proto=timetable`、`?proto=cinematic` 或 `?proto=linear`。
- **新功能要附白話導讀**（`docs/導讀_XX`），commit 訊息用繁體中文。

## 5. 協作方式（建議）

- `main` 保持隨時可以 Demo。新功能開分支，例如 `feat/xxx`，做完開 Pull Request 給對方看。
- 推上 GitHub 後，CI 會在 Windows 和 Linux 各跑一次，要全部通過（Mac 靠本機的 `npm run predemo`）。
- 要加新套件前先討論；版本選已經發布兩週以上的。
- 寫流程測試時，動畫裡只出現幾秒的字不要直接等它「看得到」（慢的機器上會錯過），改用 `e2e/seen.ts` 的 `watchFor`＋`expectSeen` 驗「出現過沒有」。

## 6. 常用指令

| 指令 | 做什麼 |
|---|---|
| `npm run dev` | 開發伺服器 |
| `npm test` | 單元測試 |
| `npm run e2e` | 流程測試＋無障礙檢查 |
| `npm run predemo` | 推程式前一鍵全檢查 |
| `npm run perf` | 量手機 4G 的首頁載入時間（LCP 要在 2.5 秒內） |
| `npm run build:pages` | 打包 GitHub Pages 版 |
