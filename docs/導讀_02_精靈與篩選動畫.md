## 1. 一句話

使用者現在可以從介紹頁一路走完：**四步精靈填條件 → 看五道關卡一道一道打勾 → 拿到三個方案**。條件太嚴時，動畫停在卡住的那一關，並給「一鍵放寬重算」。

## 3. 精靈（`src/features/wizard/`）

**比喻**：店員一題一題問，問完一題就把下一張點菜卡滑到你面前。

| 步驟 | 檔案 | 對應決策 |
|---|---|---|
| ① 地點 | `steps/StepPlace.tsx` | 縣市鎖住（Q17b）、商圈大卡片（Q45、Q46）、出發站可搜尋 |
| ② 時間 | `steps/StepTime.tsx` | 月曆只開放有資料的日子（Q47）、雙頭時間滑桿（Q48）、太短柔性提醒（Q70）、「回到 XX 站」（Q97） |
| ③ 娛樂 | `steps/StepFun.tsx` | 只有電影、其他「即將開放」（Q31）；「幫我挑」預選（Q50）；指定片名就藏起片型（Q93）；沒場次時建議換日期（Q94） |
| ④ 餐飲與預算 | `steps/StepFood.tsx` | 分段按鈕＋「12 分 ≈ 1 公里」（Q52）、飲食限制收起（Q51） |

共用的部分：

- `WizardPage.tsx`：外框、左右滑動轉場、按鈕規則（Q26：中間步驟右下角小按鈕，最後一步滿版）。
- `WizardProgress.tsx`：頂部 ①②③④，填完的可以點回去（Q25）；「清空重來」要在畫面內再確認一次（Q102）。
- `validation.ts`：每一步「填完沒」的判斷，有測試。

**跟決策不一樣的一個小地方**：時間滑桿最晚只到 **23:45**，不是 24:00，因為 API 規定時間不能跨午夜。

## 4. 五道關卡動畫（`src/features/result/FilterRun.tsx`）

**比喻**：像對發票，一張一張對、一格一格打勾（竹老師的建議）。

1. 按下「排出接得上的行程」後，先顯示「正在找出所有可能的組合…」。
2. 後端資料一回來，五道關卡依序打勾：趕得上開演 → 趕得上點餐 → 走路不超過 N 分 → 趕得上回程車 → 每人不超過 $N。
3. 大數字從 1,880 往下跳，每關旁邊寫「−820 組」。這需要後端回傳每關剔除數（API 變更提案 #7），沒有的話只會在最後跳到結果。
4. 總長大約 3 秒。後端越慢，打勾越快，總長盡量不變（Q54）。
5. 右下角可以「略過動畫」。

**什麼時候播、播多長**：

| 情況 | 動畫 |
|---|---|
| 從精靈按「排出接得上的行程」 | 完整版（約 3 秒） |
| 在無解畫面按「一鍵重算」 | 短版（約 1 秒） |
| 在結果頁按重新整理 | 不播（Q62）；只會短暫顯示錶盤，等資料回來 |

## 5. 無解畫面（`src/features/result/NoSolution.tsx`）

動畫停在卡住的那一關打 ✗，接著顯示：

> 這組條件，找不到每段都接得上的行程。卡在「每人不超過 $500」這一關。

下面是後端算好的放寬建議，每一個都是按鈕，按了直接重算（Q23）。

**怎麼預覽**：在網址加上 `?mock=no_solution`，並把預算設在 $800 以下。

## 6. 這一版發現並修掉的問題

| 問題 | 原因 | 修法 |
|---|---|---|
| 月曆格子大到佔滿半個畫面 | 用了「正方形格子」，寬度一拉長高度跟著變大 | 改成固定高度，月曆最寬 24rem |
| 「你有 2.5 小時」其實是 2 小時 15 分 | 四捨五入到半小時 | 改成直接顯示「N 小時 M 分」 |
| 動畫結束後網址的 `?mock=…` 不見了 | 清除「重播」記號時連查詢參數一起丟了 | 保留網址查詢參數 |

## 7. 測試時要知道的一件事

**同一個瀏覽器開兩個分頁，會共用同一份暫存**（條件、試做版）。在一個分頁改條件，另一個分頁重新整理後也會變。正式使用沒有影響，但兩個人同時在同一台電腦上測試時會互相干擾。
