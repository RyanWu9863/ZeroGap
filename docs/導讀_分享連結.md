# 導讀：分享連結

給組員和使用者看的白話說明。完整規格在 `docs/backend-spec.md` 的 6.8。

## 1. 這是什麼

想像去餐廳領**取餐號碼牌**。

- 行程排好了，後端把它放在「櫃台」。
- 你拿到一個號碼，就是連結最後那串編號。
- 7 天內，拿號碼來就領回**同一份**行程，不用重排。
- 超過 7 天，櫃台就清掉了。

這樣在 AI 助理（例如 Claude）排的行程，也能點連結看到網頁上的時間軸和每段緩衝。

## 2. 怎麼用

**網頁**
- 排好之後，網址會變成 `/p/編號`。把這個網址傳給朋友就行。
- 這一段是前端第 4 批才做，目前後端先準備好。

**AI 助理**
- 讓 AI 呼叫 `plan_date`。
- 回傳裡有一個 `share_url`，把它給使用者，點開就是網頁版。

**直接打 API**（開發時檢查用）
```bash
curl http://localhost:8000/api/plans/<job_id>
```
`<job_id>` 就是連結最後那串 32 碼。

## 3. 要設定什麼

在 `.env` 填：

```
PUBLIC_WEB_BASE_URL=http://localhost:5173
```

- 這是網頁的網址。本機 Demo 就填本機前端的網址。
- **沒填就不給連結。** 這樣本機開發時，不會給出一個打不開的網址。
- 前端分享頁（第 4 批）做好前先不要填，否則連結會打不開。
- 想改保留時間，用 `SAVED_PLAN_TTL_SECONDS`（秒，預設 604800＝7 天）。
- Redis 記憶體用超過七成時，這次就不存（`SAVED_PLAN_MAX_MEMORY_RATIO`，預設 0.7）。

## 4. 隱私

- 編號是 32 碼亂數，別人猜不到。
- 但**拿到連結的人，看得到整份內容**。
- 如果你是用「目前位置」出發，連結打開的內容會有你的出發座標和出發地名稱。
- 所以前端分享時會先提醒你：「連結會包含你的出發位置」。
- 錯誤（例如排不出來）不會被存。

## 5. 出問題時

**打開連結出現 404**，有兩種原因：
1. 編號格式不對（不是 32 碼小寫十六進位：0–9、a–f）。例如複製少了一截。
2. 超過 7 天，櫃台已經清掉了。

訊息會寫：「找不到這份行程，可能已經超過 7 天」。

**Redis 滿了，存不進去**
- 規劃照常進行，你照樣拿到結果。
- 只是這次沒有連結（MCP 也不會附 `share_url`）。

**去哪看日誌**
```bash
docker compose logs api | grep 分享
```
看到「分享用的行程存不進 Redis」就是上面那種情況。
