## 1. 專案現況總結

### 1.1 技術架構【事實】

| 層 | 用什麼 | 出處 |
|---|---|---|
| 框架 | React 19、Vite 8、TypeScript 7 | `package.json` |
| 樣式 | Tailwind CSS v4、shadcn/ui（底層 @base-ui/react） | `src/index.css`、`src/components/ui/` |
| 路由 | React Router 8，`createBrowserRouter`；系統幕後頁延遲載入 | `src/app/router.tsx` |
| 狀態 | Zustand＋persist，共 5 份暫存（zg-plan、zg-proto、zg-demo、zg-trial、zg-present） | `src/store/`、各 feature 的 `*Store.ts` |
| 資料 | TanStack Query＋zod 驗貨；`VITE_USE_MOCK` 預設用假資料 | `src/api/` |
| 動畫、圖表 | Motion、Recharts（只在系統幕後頁） | — |
| 測試 | Vitest 37 個單元測試；Playwright 8 條流程 × 3 種瀏覽器 | `src/**/*.test.ts`、`e2e/flows.e2e.ts` |
| 部署 | Dockerfile＋nginx；GitHub Pages workflow（**尚未發布**） | `Dockerfile`、`.github/workflows/pages.yml` |

### 1.2 目錄結構【事實】

```
src/
├── api/          唯一的對外出入口：schemas（zod）、client（假資料開關）、queries
├── mocks/        有解、無解、低信心、options、status、基準條件
├── store/        planStore（使用者條件）、demoStore（展示模式）
├── components/ui shadcn 產生的 button、popover
├── shared/       lib（純函式＋測試）、ui（BufferChip、Money、StepIcon）、brand、theme
├── app/          AppShell、router、ProtoSwitcher、PageLoading
└── features/     intro、wizard、result、behind、trial、present（依功能分資料夾）
```

規模：`src/` 加上測試和腳本，總共約 4,600 行，最大的檔案是 `schemas.ts`（164 行）。檔案都很小，分層清楚。

## 3. 問題與風險清單

依嚴重度排序。

| # | 問題【事實】 | 影響【建議】 | 嚴重度 |
|---|---|---|---|
| R1 | 預設和基準條件的日期寫死 `2026-10-30`；精靈只要「有填日期」就放行；寫進瀏覽器暫存的舊日期會一直留著 | 第 13 天試用（10/31～11/1）和 Demo（11/2）時，10/30 已經過了：精靈會帶著過去的日期送出，畫面顯示「10/30（五）」。目前假資料照樣回傳有解，**看起來正常，其實不合理**；評審一看日期就會發現 | 高 |
| R2 | 路由沒有 `errorElement`，也沒有 `*` 路徑 | 打錯網址，或任何元件出錯，都會顯示 React Router 預設的**英文白底錯誤頁**；GitHub Pages 的 404.html 也會落到這裡 | 高 |
| R3 | `StepShell` 和 `BehindPage` 在載入失敗時沒有錯誤狀態 | 用假資料時不會發生；接上任何真實資料來源後，一失敗就**永遠轉圈** | 中 |
| R4 | `ResultError` 把「連不上」和「資料格式對不上（zod 驗貨失敗）」都顯示成「連不上」 | 除錯時看不出是哪一種問題 | 中 |
| R5 | persist 沒設版本 | 以後改了欄位或預設值，舊使用者的瀏覽器會帶著舊格式的資料，可能出現怪畫面 | 中 |
| R6 | 三版設計的樣式散在 21 個檔案、共 61 處 `cine:`／`lin:` | 投票後如果要刪掉落選版，要改的地方很多，容易漏改 | 中 |
| R7 | 32 個手寫按鈕，各自的圓角、高度、hover 樣式略有不同 | 介面一致性不好，改風格時要改很多地方 | 低 |
| R8 | 主程式 gzip 後 258 KB，還沒用真的手機網路量過 | 4G 的首頁載入時間不清楚 | 低（先量再說） |
| R9 | 平板沒稽核過 | 如果評審用 iPad 看，版面可能不好看 | 低（看 Demo 用什麼裝置） |

## 4. 後續開發 Roadmap

### P0：必須先解決

#### P0-1　日期不會過期
- **目的**：試用和 Demo 當天，日期都要合理。
- **為什麼**：R1。試用日已經晚於 10/30。
- **預期結果**：
  - 預設日期改成「`available_dates` 裡最近的一天」，不再寫死。
  - 精靈第②步驗證：日期必須在可選清單裡。
  - 瀏覽器暫存或網址帶進來的過去日期，會被清掉，並提示「原本的日期已經過了，請重新選」。
- **涉及檔案**：`mocks/request.ts`、`store/planStore.ts`、`wizard/validation.ts`（＋測試）、`wizard/steps/StepTime.tsx`、`result/urlState.ts`、`result/useResultState.ts`、`present/PresentMode.tsx`、`intro/scenarios.ts`、`e2e/flows.e2e.ts`、`shared/lib/lib.test.ts`、`docs/彩排腳本_第14天.md`（備用網址）
- **前置**：【待確認】Q1：日期要固定還是跟著今天走。
- **風險**：測試裡寫死了 `10/30（五）` 的斷言要一起改；`validation.ts` 是純函式，最好維持不讀現在時間，改成由呼叫的地方傳入可選清單。
- **驗收**：
  - Playwright 把時鐘設成 2026-11-02，精靈預設日期可以選，也送得出去。
  - 帶著 10/30 的舊暫存打開精靈 → 停在第②步，要求重新選日期。
  - 開啟 `date=2026-10-30` 的網址 → 有提示，不會靜靜地照算。
  - `npm run predemo` 全過。
- **順序**：1

#### P0-2　錯誤頁和找不到頁面
- **目的**：任何出錯都顯示白話中文，並給一條出路。
- **為什麼**：R2。
- **預期結果**：新增 `app/RouteError.tsx`，沿用 `ResultError` 的版型；加上「回首頁」和「重新整理」按鈕，三版風格都適用；router 加上 `errorElement` 和 `{ path: '*' }`。
- **涉及檔案**：`app/router.tsx`、新檔 `app/RouteError.tsx`、`e2e/flows.e2e.ts`
- **前置**：無
- **風險**：低。錯誤頁不能再依賴可能已經壞掉的東西（例如 store），所以要盡量單純。
- **驗收**：`/abc` 顯示中文的「找不到這一頁」；故意讓一個元件出錯，看到的是中文錯誤頁；新增 1 條 E2E。
- **順序**：2

#### P0-4　Mac 和 Windows 都能開發（10/20 追加，✅）
- **目的**：組員有人用 Mac、有人用 Windows，大家都要能 `npm install`、開發、測試、打包。
- **為什麼**：盤點時發現下面這些地方只有 Mac 能用【事實】。
  - `build:pages` 用了 `${PAGES_BASE:-…}` 和 `cp`，Windows 的命令列看不懂。
  - `scripts/make-og.mjs`、`make-icons.mjs` 用 `new URL(...).pathname` 當檔案路徑，Windows 上會變成 `/C:/…`，存檔失敗。
  - 沒有統一換行字元，Windows 的 Git 可能把檔案改成 CRLF，nginx 設定進到 Linux 容器時可能出錯。
  - 沒有寫清楚要用哪個 Node 版本。
- **做了什麼**：
  - `build:pages` 改用 Node 腳本 `scripts/build-pages.mjs`；圖片腳本改用 `fileURLToPath`。
  - 新增 `.gitattributes`（一律 LF）、`.editorconfig`、`.nvmrc`（24），並在 `package.json` 設定 `engines`（>=22.12）。
  - 新增 `.github/workflows/ci.yml`：在 macOS、Windows、Linux 各跑型別、lint、測試、打包和 Chromium 流程測試。
  - README 加上「Mac 和 Windows 都能開發」一節，包含 PowerShell 的寫法。
- **檢查過的**【事實】：lockfile 已經包含 Windows 版的原生套件（rolldown、oxlint、tailwind oxide、lightningcss、TypeScript 7），在 Windows 上 `npm ci` 不會缺套件；現有檔案都是 LF。
- **驗證**【事實】（10/22）：GitHub Actions 的 `windows-latest` 跑 `npm ci`、型別、lint、單元測試、打包 Pages 版、Chromium 流程測試全部通過（PR #1、#2 的 CI）。組員的 Windows 電腦第一次跑時，如果遇到問題再回報。

### P1：下一階段的核心

#### P1-1　選項載入失敗的畫面
- **目的**：精靈和系統幕後在資料抓不到時，要顯示「重試」，不是一直轉圈。
- **為什麼**：R3。
- **預期結果**：`StepShell` 多一個 `error`＋`onRetry`；`StepPlace`、`StepTime`、`StepFun`、`StepFood` 傳入 `isError`／`refetch`；`BehindPage` 也分出錯誤狀態。另外加一個前端的假資料情境 `?mock=options_error` 方便測試，這只是前端自己的模擬，不是假設新的 API。
- **涉及檔案**：`wizard/steps/*.tsx`、`behind/BehindPage.tsx`、`api/client.ts`
- **前置**：P0-2（共用錯誤畫面的版型）
- **風險**：低
- **驗收**：用 `?mock=options_error` 開精靈，看到重試按鈕，按了之後恢復；新增 1 條 E2E。
- **順序**：3

#### P1-2　錯誤分類＋請求逾時
- **目的**：分得出「連不上」和「資料格式不對」；請求卡住時不要無限等。
- **為什麼**：R4。
- **預期結果**：`client.ts` 把 zod 錯誤包成可以辨識的錯誤類型；開發時在 console 印出是哪個欄位不對；使用者畫面維持白話。`fetch` 接上 TanStack Query 提供的 `signal`，並設定逾時。
- **涉及檔案**：`api/client.ts`、`api/queries.ts`、`result/ResultStates.tsx`
- **前置**：P1-1
- **風險**：低。只改出入口，畫面元件不受影響。
- **驗收**：單元測試：格式錯的假回應會被認成「格式錯誤」；E2E：結果頁錯誤畫面的文字正確。
