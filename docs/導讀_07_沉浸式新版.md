> 2026-10-23。設計方案和取捨：`docs/沉浸式體驗_第一階段盤點與設計方案.md`；交接紀錄：`docs/沉浸式體驗_進度交接.md`。

## 1. 一句話

把「顯示結果的畫面」升級成「看得到篩選、選擇、決策過程的畫面」：誠實的篩選漏斗、電影式三方案、真正有順序的路線地圖、三種幕後視覺化。**全部做在開關後面**，網址加 `?exp=1` 才看得到，預設畫面（試用和三版比較用的）完全沒變。

## 2. 怎麼打開

| 方法 | 說明 |
|---|---|
| 網址加 `?exp=1` | 打開，會記在瀏覽器；`?exp=0` 關掉 |
| 左下角試做版切換列的「新版體驗」 | 同上，點一下切換 |

三個試做版（A／B／C）都能搭配新版一起看，例如 `?exp=1&proto=cinematic`。

## 3. 最重要的原則：不假裝

比喻：這像體育轉播的「賽後重播」。比賽（排程服務的計算）是一次算完、一次回傳的，中途沒有直播訊號。所以：

- **等回應的時候**：只說「已送出、等回應」和真的等了幾秒，五道關卡都標「待檢查」，**不畫任何數字**。
- **回應到了**：用回應裡真實的「每一關淘汰幾組」做重播，畫面寫明「這次結果的逐關重播」。
- **後端沒給的東西就說沒給**：個別被淘汰的組合（API 提案 #10）、排程服務每一步花多久，都沒有回傳，畫面就寫「沒有回傳」，不編。

## 4. 四塊新東西

### 4.1 篩選漏斗（結果頁，`result/funnel/`）
- 點陣：一個點 ≈ 全部組合 ÷ 120。每過一關，被那一關淘汰的點變灰往下掉；五關過完，留下的點收成 3 個方案節點。
- 每道關卡可以展開，看「這一關檢查什麼」和「淘汰幾組、還剩幾組」。展開過就不會自動跳走，改按「看行程」。
- 無解時停在卡住的關卡（紅色），後面的關卡標「沒檢查」。
- 點的去留由 `funnelModel.planDots` 照真實比例算出（有單元測試）。

### 4.2 電影式三方案（結果頁，`result/stage/`）
- 選中的方案在中央放大，另外兩個縮小退到左右。點側邊或按 ←／→ 換到中央。
- 每張卡：特色標籤、推薦理由、出門 → 回到站、電影、餐廳、全程多久、花費、最緊緩衝，加上一條「時間比例緞帶」當主視覺（沒有照片素材，決策 Q43 也定了用程式畫）。
- 「看完整行程」：卡片從原位放大成對話框（共享元素轉場），背景變暗、點不到；Esc、點背景、按 X 都會縮回原卡片，焦點回到按鈕。
- 時間軸照樣留在頁面上（決策 Q36：主角是時間軸），對話框是放大版＋地圖＋花費。
- 手機改成左右滑的單張大卡，詳情從底部滑出。

### 4.3 行程路線地圖（`result/map/`）
- **路線示意**（預設）：照時間軸順序編號，實線搭車、虛線走路；點站點看那一站的時間和要做的事。
- **Google 地圖**：真實底圖＋編號標記＋站和站之間的連線。
  - 連線是**直線**，畫面寫明「不是導航路線」；要畫真的道路路線需要另外開 Google Routes API（沒做）。
  - 假資料沒有座標，用一張「示意座標」表（車站、影城、餐廳的大概位置），畫面標「示意座標」。後端給了座標就用後端的。
  - 沒設金鑰、缺座標、載入失敗、金鑰被拒，都會自動退回示意圖並說明原因。
- 切換模式時，選中的站和地圖視角都會保留；換方案時跟著換。

### 4.4 系統幕後三種視覺化（`behind/views/`）
同一份回應，三個分頁：

| 分頁 | 回答的問題 | 資料 |
|---|---|---|
| A 篩選漏斗 | 組合怎麼一關一關被篩掉？ | 每關剔除數；原本的長條圖、桑基圖收在「看圖表」 |
| B 決策時間軸 | 系統照什麼順序做了哪些事？ | 送出、收到時間和來回秒數是瀏覽器量的（真的）；排程服務內部每一步標「沒有回傳時間」 |
| C 決策比較 | 入選的方案差在哪？ | 五道關卡、緩衝、回到站、花費、Jev 機率並排，每列文字標「最佳」 |

先做三版讓團隊比較，再決定正式用哪一版。

## 5. Google 地圖要怎麼設定

1. Google Cloud 建專案、**綁帳單**，開「Maps JavaScript API」。
2. 建立「瀏覽器金鑰」，**限制 HTTP 參照網址**（例如 `http://localhost:5173/*` 和正式網域）。瀏覽器金鑰一定看得到，所以靠限制網域保護。
3. 複製 `.env.example` 成 `.env`，填 `VITE_GOOGLE_MAPS_KEY=你的金鑰`。
4. 正式上線另外建一個地圖 ID 填 `VITE_GOOGLE_MAPS_MAP_ID`（編號標記需要）；留空用 Google 的 `DEMO_MAP_ID`，只適合開發。

**驗證狀態**：這台開發環境沒有金鑰，只驗證到「Google 的程式會載入、假金鑰會被拒絕並退回示意圖」。**有真金鑰時的地圖畫面還沒親眼看過**，設定好後請實際打開確認一次。

## 6. 測試

- 單元測試：點陣比例、方案重點整理、時間緞帶、路線整理（`funnelModel.test.ts`、`planFacts.test.ts`、`route.test.ts`）。
- 流程測試 `e2e/experience.e2e.ts`：等待時沒有假進度（用假時鐘停住回應）、收斂、展開關卡、無解、方案切換和方向鍵、對話框開關和焦點、地圖編號和模式切換、平板手機不左右晃、幕後三個分頁、減少動態。
- 無障礙：三個試做版 × 漏斗、方案舞台、詳情對話框、幕後三個分頁，axe 掃描沒有嚴重問題。
- 這台環境只有 Chromium（也用它模擬 iPad）；**WebKit 和 iPhone 請在 Mac 上 `npm run predemo` 確認**。

## 7. 評審可能會問

| 問題 | 回答 |
|---|---|
| 動畫是真的在算嗎？ | 不是即時的。排程服務一次算完回傳，動畫是用回傳的真實數字「重播」，畫面上有寫。 |
| 為什麼看不到被淘汰的是哪幾組？ | 後端目前只回傳每一關淘汰幾組，沒有回傳個別組合（API 提案 #10，排在 v2）。 |
| 地圖上的線是實際路線嗎？ | 不是，是站和站之間的直線示意，畫面上有標。實際路線請按「在 Google 地圖查看完整路線」。 |
| AI 在哪裡？ | 使用者畫面依決策 Q16 不提 AI；排序（Jev）和機率放在系統幕後。LLM 目前未啟用。 |
