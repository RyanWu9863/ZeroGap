# ZeroGap 前端重新設計：設計規格

> 2026-11-07｜狀態：待使用者審閱｜範圍：子專案 ②「前端重新設計」（① 連結取餐號、③ MCP 再優化各有自己的規格）
> 依據：團隊 repo `RyanWu9863/ZeroGap` main `70dcc2a` 的 `frontend/`、優化版私人 repo `Samuelsunshine/zerogap-frontend` main `4e79b2f`、學長姐作品 Justmarket、awesome-opus5-5-videos（程式即時生成的動畫）

## 1. 目標

把 `frontend/` 從「專題 Demo」做成**正式產品**：讓人真的想用，程式可以上線，並且把核心價值「零空檔：保證接得上」放在畫面中央。完成度以學長姐的 Justmarket 為參考：有導覽、有方法頁、用真數字說故事、有頁尾和資料來源。

**成功的樣子**
- 第一次來的人在手機上 **1 分鐘內**排出行程，看得懂「每段之間有幾分鐘緩衝、哪一段最緊」。
- 使用者在 AI 助理裡排好行程後，點 MCP 給的連結，看到的是**同一份**行程。
- 上台時，網頁和簡報（發表會版，錶盤＋液態動畫）看起來是同一個品牌。
- `npm run predemo` 全過；慢速 4G 首頁 LCP < 2 秒；axe 零嚴重問題。

## 3. 頁面和流程

### 3.1 網站地圖

| 路徑 | 頁面 | 導覽列 |
|---|---|---|
| `/` | 首頁：點陣剪枝＋快速條件 | 有 |
| `/plan/:step` | 完整條件（現有四步精靈改造），從首頁的「更多條件」進入 | 不單獨列 |
| `/result?…條件` | 送出規劃、排程中漏斗；排好後網址換成 `/p/:id` | — |
| `/p/:id` | 結果頁（也是分享頁、MCP 連結開的頁） | — |
| `/method` | 方法：捲動解說 | 有 |
| `/ai` | 在 AI 助理裡使用 | 有 |
| `/about` | 關於：團隊、資料來源授權 | 有 |
| `/behind` | 幕後（上台用，知道網址才進得去） | **沒有** |
| `*` | 中文 404 | — |

手機的導覽列收在底部，四顆按鈕：排行程、方法、AI 助理、關於。電腦版放在頂部。頁尾放資料更新時間（`/api/status` 的 `data_updated_at`）、資料來源、GitHub。

### 3.2 主流程

1. **首頁**：標題「電影、晚餐、回家的車，每一段都接得上。」＋點陣剪枝動畫＋三格快速條件（從哪出發、哪天、每人預算）＋「排行程」。其他條件用預設值：商圈依出發點、片型不限、23:30 前到家；預設值和現有 `planStore` 一致，日期跟著今天走。「更多條件」進入完整的四步精靈。
2. **排程中**（同一頁，不跳轉）：真進度漏斗（4.3）。
3. **排好**：網址用 `history.replaceState` 換成 `/p/{job_id}`，重新整理不會重排。
4. **結果頁**：錶盤＋瓶頸聚光燈 → 逐段時間軸 → 地圖 → 花費 → 「這個方案怎麼來的」。三個方案左右滑動切換（觸控、鍵盤 ←／→）。動作按鈕：分享（複製 `/p/:id`；手機用系統分享選單）、改條件重排、加到行事曆（.ics，在瀏覽器裡產生）。
5. **排不出來**：用後端的 `reasons` 說明哪個條件擋掉最多，並提供一鍵放寬（沿用 `relax.ts`）。

### 3.3 分享頁的特殊狀態

- 上方一行說明：「這份行程在 11/7 21:03 排好，班次已確認」。
- **過期**（超過 `expires_at`，或出發時間已經過了）：「這份行程已經過期」＋「用同樣條件重排」。
- **找不到**（404）：「找不到這份行程，可能已超過 7 天」＋回首頁。

## 4. 視覺系統和招牌動畫

### 4.1 主題

- 「夜」：深色、錶盤刻度、青色光。「日」：同一套設計語言的亮色版。預設跟著系統，可以手動切換（存在 localStorage）。
- 字體：思源黑體（內文）、Archivo（大數字）、IBM Plex Mono（時刻），跟簡報動畫頁一致；沿用優化版的字型非同步載入，不擋畫面。
- 顏色：青色是唯一的主色，代表接得上的路線。緩衝的三色燈（寬鬆、剛好、太緊）是語意色，門檻沿用 `shared/lib/buffer.ts`。
- 元件：統一用 shadcn 的 Button 等元件（順便完成優化計畫 P2-1）。

### 4.2 首頁：點陣剪枝

- Canvas 2D。一個點＝一種組合；依序經過關卡，每過一關熄掉一批，最後剩 3 個亮點，飛成三張方案卡。
- 數字來源：這台瀏覽器排過的話，用最近一次的 `stats.combinations`、`stats.feasible`；沒排過就用一份**真後端跑出來的範例**（`api/__fixtures__/backend-plan-result.json`），畫面標「示範」。
- 點太多時抽樣：手機上限約 4,000 點、電腦約 12,000 點，畫面照實寫「每點代表 N 種組合」。
- 標題文字是 LCP 元素，Canvas 在標題出現後才開始畫。

### 4.3 排程中：真進度漏斗

- 7 個階段（`features/result/stages.ts`）一道道點亮；`filtering` 帶回的 `combinations`、`feasible` 讓數字跟著跳。
- `queued` 顯示「前面還有 N 個人」；`waiting_quota` 顯示「交通資料查詢中，約 N 秒」。
- 用 `aria-live="polite"` 播報目前的階段。

### 4.4 結果頁：錶盤＋瓶頸聚光燈

- SVG 錶盤：從出發到到家是一圈弧，每段（走路、電影、餐廳、搭車、等待）一種顏色。
- 最緊的一段緩衝（`min_buffer_minutes`）打聚光燈；點它會說明後果，依 `buffer_gate` 決定文案：`showtime`（趕不上開演）、`last_order`（趕不上最後點餐）、`return_trip`（趕不上預定那班車）、`latest_return`（趕不上末班車）。
- 錶盤下面是逐段的時間軸清單，所有資訊都有文字版。

### 4.5 方法頁：捲動解說

- 一道關卡一個畫面，往下捲時展開（IntersectionObserver＋Motion），每一關配一個真數字（同一份範例）。
- 講通用原理：怎麼算緩衝、為什麼要查最早到、最晚走的車、資料從哪來、多久更新一次。不出現 Jev、LLM。

### 4.6 動態和效能規則

- 不加動畫套件：用 Canvas 2D、SVG、已經有的 Motion。
- `prefers-reduced-motion`：直接顯示每個動畫的最後一格。
- 動畫元件都延遲載入；慢速 4G 首頁 LCP < 2 秒（`npm run perf` 量）。
- Recharts 只在幕後頁用，延遲載入。

## 5. 結果頁的地圖（D10）

- **限制**：Google 來源的餐廳只有 `place_id`、沒有座標（Google 規定不能存），所以只能用 Google 地圖，不能用 OpenStreetMap。
- **做法**：Maps JavaScript API，透過 `@vis.gl/react-google-maps`（優化版用過 1.10.1；實作時選發布滿兩週的版本並固定版號，**新增前再問使用者一次**）。
  - 標記：出發點、影城、餐廳、車站，依時間軸編號；`place_id` 的地點用 Places 查位置。
  - 走路段：用 Google 的路線服務畫真的步行路徑。
  - 搭車段：照我們排的 TDX 班次，畫起訖站之間的路線，標車種、站名；不用 Google 自己建議的班次。
  - 地圖配色跟著夜／日主題（地圖 ID 的樣式）。
  - 「在 Google 地圖開啟」：整趟一顆、每段一顆，用現有的 `shared/lib/maps.ts`（Maps URLs，不用金鑰）。
- **省錢**：路線結果用分享編號存在 localStorage，同一份行程不重複查。
- **金鑰**：`VITE_GOOGLE_MAPS_KEY`、`VITE_GOOGLE_MAPS_MAP_ID`，瀏覽器金鑰要限制網域。由使用者到 Google Cloud 申請、綁帳單。**實作前先查官方最新的價目和免費額度**，寫進導讀。
- **退路**：沒有金鑰、載入失敗、金鑰被拒時，自動改成示意路線圖＋Google 地圖連結，並說明原因。
- 地圖在捲到附近時才載入，不影響 LCP。

## 6. 幕後（D11）

- **「這個方案怎麼來的」**（結果頁，每個方案一個，可展開）：這一次的真數字（`stats.combinations` → `stats.feasible` → 3）、`highlight.reason`、備選的電影、餐廳、班次（`alternatives`）、資料更新時間。不出現 AI 字眼。
- **幕後頁 `/behind`**（不放在導覽列，上台用）：用夜主題重畫漏斗、桑基圖、決策表；直接講 Jev 機率（`probabilities`）、哪些題目交給 LLM 代選（`decided_by`）、MCP 工具清單和一次呼叫的流程。資料用最近一次排程或示範範例。

## 7. 資料流和介面

- 新頁面只透過 `api/`（`client.ts`、`sse.ts`、`planRuns.ts`、`queries.ts`）拿資料；回應都經過 zod 驗證。
- **跟子專案 ① 約好的介面**（細節以 ① 的規格為準）：
  - `GET /api/plans/{id}` → `{ result: PlanResult, request: PlanRequest, created_at, expires_at }`；不存在或過期回 404。
  - 結果存在 Redis，保留 7 天；`id` 就是 `job_id`（32 碼亂數）。
  - MCP `plan_date` 多回傳 `share_url`，網址前半段由設定檔 `PUBLIC_WEB_BASE_URL` 決定。
- **假資料模式**（GitHub Pages 展示站）：假伺服器把排過的結果存在 localStorage，所以同一台瀏覽器打得開 `/p/:id`。

## 8. 出錯時

從優化版搬回，照新設計重寫畫面：
- 錯誤分四種（連不上、等太久、錯誤代碼、格式不對，`api/errors.ts`）；逾時：排行程 30 秒，其他 10 秒；只有可重試的錯誤才自動重試。
- 中文的「找不到這一頁」和「這一頁出了點問題」，錯誤頁分兩層（頁面出錯時外框還在）。
- 暫存加版本號，逐欄驗證（`store/persistSafe.ts`）。
- 分享頁的過期和找不到（3.3）。地圖的退路（第 5 節）。
