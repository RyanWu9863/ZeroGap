## 2. 新電腦的安裝步驟

需要：Git、Docker Desktop、uv（會自己裝 Python 3.13）、Ollama。

```bash
git clone zerogap-backend.bundle ZeroGap
cd ZeroGap
uv sync
ollama pull qwen2.5:3b
```

1. **`.env` 不在 bundle 裡**（有金鑰）。複製 `.env.example` 成 `.env`，填 `TDX_CLIENT_ID`、`TDX_CLIENT_SECRET`。`TDX_MODE` 可以設成 `real`（真的 TDX）或 `mock`。
2. 開 Docker，啟動全部服務（會自動跑 migration）：
   ```bash
   docker compose up -d --build
   ```
3. **依序**寫入資料（順序有關係）：
   ```bash
   uv run python -m app.seed.demo
   uv run python -m app.jobs.refresh stations
   uv run python -m app.jobs.refresh hubs
   OLLAMA_BASE_URL=http://localhost:11434 uv run python -m app.jobs.refresh osm
   ```
   - 示意資料先寫：影城、場次還要靠它（開眼爬蟲還沒做好）。之後匯入真的車站、餐廳時，示意的會自動停用。
   - `osm` 第一次要判斷約 900 家，每家約 2.4 秒，**約 35～40 分鐘**。中途中斷沒關係，重跑只會補還沒判斷的。
4. 確認：`curl localhost:8000/api/health`、`curl "localhost:8000/api/stations?county=Taoyuan"`。
5. 測試：`uv run pytest`（整合測試會建自己的 `zerogap_test` 資料庫和 Redis 第 15 號資料庫，不會碰開發資料）。

## 3. 容易踩到的地方

- **Ollama 網址**：`.env` 的 `OLLAMA_BASE_URL=http://host.docker.internal:11434` 是給 Docker 裡的 worker 用的。**在本機直接跑匯入工作時要改成 `http://localhost:11434`**（上面的指令用環境變數覆蓋）。舊電腦就是這裡設錯，884 家全部判斷失敗。現在連續失敗 5 次就會先停。
- **PostgreSQL 對外是 5433**：舊電腦的 5432 被另一個 PostgreSQL 佔用。新電腦如果 5432 是空的也不用改，照 5433 就好。
- **TDX 限流**：每分鐘 5 次，模擬版也照樣限流（使用者決定）。開發時想快可以在 `.env` 設 `TDX_PER_MINUTE=1000`，但用真的 TDX 時不要改。
- **改了 migration 要重建映像檔**：`docker compose up -d --build`。`migrate` 容器用的是建映像檔時的程式，不認得新的 revision 會失敗（`Can't locate revision`），api、worker 也跟著起不來，proxy 回 502（2026-10-21 實際碰到）。
- **`alembic.ini` 只能有 ASCII**：Windows 用 cp950 讀。
- **Windows 的事件迴圈**：API 的整合測試在 conftest 設了 `WindowsSelectorEventLoopPolicy`（psycopg 非同步模式需要）。
- **nginx**：用 Docker DNS 重新解析 api（api 重開會換 IP），並傳下 `X-Accel-Buffering`。

## 4. 開眼電影網：給接手的人（J 的實作重點）

- 只有今天和之後 1～2 天的場次；每天 06:00、18:00 抓（使用者決定）。每頁間隔幾秒，User-Agent 帶專案名稱。報告註明「僅供學術展示」（使用者決定照抓）。
- 影城清單：`https://www.atmovies.com.tw/showtime/a03/`，`#theaterList` 下每個 `li` 是一家（連結 `/showtime/t033xx/a03/`，下面的 `ul li` 依序是地址、電話……）。共 10 家；**兩家光影館不收**（只有節目表圖片）。
- 影城對商圈：統領威秀、桃知道威秀、in89 → 桃園區；星橋、威尼斯、新光 → 中壢；國賓八德 → 八德；美麗新台茂 → 蘆竹（南崁）。建議用地址的區（桃園區、中壢區、八德區、蘆竹區）對，或用 TDX 地理編碼後依距離歸到最近的代表點。
- 品牌：威秀 vieshow、in89、新光 skcinemas、國賓 ambassador；星橋、威尼斯、美麗新（Miramar）不在 `ticket_prices` 的五大品牌裡，票價會用 `default`。
- 場次頁 `/showtime/{影城}/a03/{YYYYMMDD}/`（今天不帶日期），日期連結在頁面上方。每部片（＋版本）一個 `ul#theaterShowtimeTable`：
  - `li.filmTitle a[href=/movie/{id}/]` 片名
  - 分級是圖檔 `cer_G/P/F2/F5/R.gif`（推測：普遍、保護、輔12、輔15、限制，未確認）；`片長：119分`
  - 版本在時間清單的第一個 `li.filmVersion`（例如「國語版」「IMAX」「4K數位修復版」），**一般場次沒有這個 li**
  - 時間是 `li`，冒號是全形「：」，例如 `12：00`；最後一個是 `li.theaterElse`（其他戲院）
  - **跨午夜**：23:30 之後的 00:10、01:40 是隔天
- 版本文字要做對照表：影廳（IMAX／IMAX版 → imax、4DX → 4dx、ScreenX、杜比、TITAN……，其他 → standard）和語言（國語版／中文版 → 中文、日語版／日文版 → 日語……）。
- 電影頁 `/movie/{id}/` 有 JSON-LD（`duration`、`description` 簡介、`countryOfOrigin`），分級要看圖檔。片型交給 Ollama 判斷（跟餐廳一樣，Jev 金鑰到了再換）。
- 影城地址轉座標：TDX 地理編碼 `Address`（`app/collectors/tdx_geocode.py` 已經有 `Geocoder.address`）。
